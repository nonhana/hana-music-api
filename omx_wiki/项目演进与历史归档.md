# 项目演进与历史归档

本目录用于把 `stash/` 中的阶段计划、迁移说明与技术债记录，整理为**可追踪、可检索、可长期留档**的项目历史档案。

## 目录目的

这套归档文档同时承担三件事：

1. 保留项目从迁移重写到发布收口的历史痕迹。
2. 把“当时怎么想”与“后来实际落地了什么”分开记录，避免旧计划继续被误读为当前真相。
3. 把历史推进脉络收口到 `omx_wiki/`，让后续接手者能从 OMX 目录直接检索阶段结论与历史判断。

## 真相优先级

当历史文档与当前仓库现实冲突时，按下面顺序判断：

1. `src/`、`tests/` 与当前可验证运行结果
2. `README.md` 与 `docs/` 中的当前面向使用者文档
3. `omx_wiki/` 中的当前快照、阶段归档与漂移判断
4. Git 历史中的已移除 已移除的历史原稿与 Git 历史记录

换句话说：**本目录负责保留历史，不负责覆盖当前代码事实。**

## 状态标签

- **completed**：阶段目标已在仓库中实际落地，并有代码/测试/文档证据支持。
- **partially-landed**：核心目标已落地，但仍有少量收口项未闭环。
- **superseded**：原文档仍有历史价值，但其中的执行判断已被后续实现或更新文档替代。
- **archived**：保留原始思路或检查清单，平时不作为当前执行入口。

## 当前结论（2026-06-05）

截至当前仓库状态：

- **Phase 5** 的回归基线已经建立并长期保留在测试中。
- **Phase 6** 的核心收尾工作已完成，残留的是质量与元信息级尾项。
- **Phase 7** 规划中的 `/demo/*` 本地调试 UI 已经真实落地。
- **Phase 8** 的大部分发布标准化工作已完成，但还没有通过正式版本标签与运行时版本元数据完成最后闭环。

因此，后续接手者不应再把 `stash/phase-5~7` 当成待执行计划，而应把它们视为**已完成阶段的历史归档**。
