# 上传链路手工验证沿革

- **状态**：archived but still applicable
- **原始来源**：`stash/upload-manual-checklist.md`

## 这份清单最初解决什么问题

上传链路（尤其是 `voice_upload`、`cloud`、NOS token 分配、多分块 multipart、XML complete 组装）并不适合只靠离线单元测试证明全部行为，因此历史上额外保留了一份手工验证清单，用于：

- 补上传相关改动的真实环境验证
- 记录单分块 / 多分块 / 异常 XML / 缺文件报错等人工检查口径
- 防止上传链路在依赖替换和边界收口后失真

## 当前为什么仍要保留

虽然仓库已经有：

- `tests/voice-upload.test.ts`
- 上传相关 helper 测试
- 服务层 multipart 适配测试

但这仍然不能完全替代真实网络、真实 Cookie、真实上传权限与真实 NOS 交互场景。因此，这份清单今天仍有保留价值。

## 当前的正确使用方式

这份清单**不是日常开发都要跑的默认步骤**，而是下面这些情况下的条件性验收：

1. 修改了 `voice_upload.ts`
2. 修改了 `cloud.ts`
3. 修改了 `src/plugins/upload.ts` / `src/plugins/song-upload.ts`
4. 修改了服务层 multipart 解析
5. 调整了上传链路的 XML helper 或 NOS 请求组装

## 当前角色定位

在今天，它更像：

- **上传专题的人工回归 SOP**
- **上传链路改动后的高风险补证手册**

而不是一个活跃 phase 的主计划文档。
