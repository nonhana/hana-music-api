## 当前阶段定位

结合当前代码、测试、README、文档构建与最小启动验证，项目现在更准确的位置是：

> **迁移主线已完成，处于 Phase 8 的发布收口阶段。**

这意味着：

- 不应再把主要精力放在重新解释 Phase 5/6/7 的目标上。
- 也不应再把 `stash/phase-7*` 看成尚未开工的 Demo UI 方案。
- 当前最合理的执行主线是：**把已落地能力整理成可正式发布、可打 tag、可自证版本状态的服务交付物。**

## 当前最接近的未闭环项

虽然本目录不承担活跃计划职责，但基于当前仓库现实，可以明确以下几项属于“还差最后一步”的收口项：

1. 运行时默认版本字符串仍是 `phase-6`，与整体项目状态不一致。
2. 仓库还没有正式版本标签，Phase 8 的“源码发布”目标未完成最后一步。
3. `docs/changelog.md` 还没有反映后续的历史归档与发布收口演进。
4. `bun run lint` 仍有 warnings，说明质量面尚未完全收干净。

## 归档使用规则

- 回看“为什么当时这么设计”：读阶段归档页。
- 判断“现在是不是还要做”：先看本页，再看 `drift-register.md`。
- 真正决定当前工程行为：回到 `src/`、`tests/`、`README.md` 与 `omx_wiki/` 当前快照。
