## 当前阶段定位

结合当前代码、测试、README、文档构建与本地服务验证，项目现在更准确的位置是：

> **迁移主线已完成，Phase 8 已完成，项目进入 `v0.0.1` 之后的正式维护起点。**

这意味着：

- 不应再把主要精力放在重新解释 Phase 5/6/7 的目标上。
- 也不应再把 `stash/phase-7*` 看成尚未开工的 Demo UI 方案。
- 当前最合理的执行主线不再是“继续做服务发布收口”，而是基于 `v0.0.1` 进入后续维护与下一阶段目标拆分。

## 当前仍值得注意的事项

虽然 Phase 8 已闭环，但当前仓库仍有两类后续工作值得单独开题：

1. `bun run lint` 仍有 warnings，质量面尚未完全收干净。
2. npm 包分发与通用库 release 需要作为独立新阶段规划，不应再混入服务发布叙事。

## 归档使用规则

- 回看“为什么当时这么设计”：读阶段归档页。
- 判断“现在是不是还要做”：先看本页，再看 `drift-register.md`。
- 真正决定当前工程行为：回到 `src/`、`tests/`、`README.md` 与 `omx_wiki/` 当前快照。
