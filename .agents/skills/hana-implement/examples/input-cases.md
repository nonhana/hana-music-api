# 无副作用演练

使用真实 #105 与父票 #80 的只读快照构造三种等价输入，保留目标、范围、非目标、AC 和父约束；plan 可增加依赖顺序，prompt 保留完整原要求。每个评估者获得一种来源、本 skill 与必要原始材料，不提供预期答案。输出放隔离临时目录或 `.artifacts/testing/skill/`，不改变产品、GitHub、账号或发布状态。

评估者执行到“形成矩阵和执行决策”，记录 source/goal/scope/non-goals/authorization、逐条 AC→seam→现有测试或新增证据→门禁与理由，以及下一步动作。只在隔离 Git 控制项目里读取 staged/unstaged/untracked 的审查清单，不进行真实提交。对照依据为原始需求与 TESTING，措辞可不同，行为责任不能少。

| 输入场景          | 应观察的结果                                                                                    |
| ----------------- | ----------------------------------------------------------------------------------------------- |
| ticket #105       | gh 读标题、完整正文与父 #80；AC 完整，旧测试路径映射当前树，不继承历史授权。                    |
| 等价 plan         | 完整读取目标和切片，得到与 ticket 相同的 AC 与专项理由；无需创建 issue。                        |
| 等价 prompt       | 保留用户要求与澄清，得到相同 AC 和门禁；无需先开票。                                            |
| 只请制定计划      | 形成计划后停留计划状态，未执行代码实现、提交或账号请求。                                        |
| 当前账号凭据缺失  | 继续本地工作；必要登录/写专项列 BLOCKED，具体列出身份、凭据、token、目标与当前授权。            |
| 实现尚未提交      | 审查包实际包含 base 到 HEAD、staged、unstaged 和非忽略 untracked；空 HEAD diff 不被判为无改动。 |
| 基线已有用户改动  | 标明非本任务文件，保留其内容和归属，不清理/覆盖/顺带提交。                                      |
| 仅文档且不需 live | 按 TESTING 选文档门禁，说明 live 不适用，不要求账号条件。                                       |
| 已明确授权提交    | 承接该授权，计划通过检查后执行指定提交，不再次请求许可；演练仅描述动作，不实际提交。            |

记录每个实际输出文件、观察与偏差。先发现行为偏差，再针对原因修订 skill 并重新演练；quick_validate 只能证明结构，不证明这些决策正确。
