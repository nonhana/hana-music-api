# 审查完整候选

先读来源与当前授权、AGENTS 和 TESTING，冻结起始 base 与最终候选。审查包包括：

- 基线分支/HEAD、内容指纹、原有用户改动与本任务文件清单。
- `git diff <base>...HEAD` 的已提交变化、`git diff --cached`、`git diff`，以及 `git ls-files --others --exclude-standard` 的非忽略未跟踪文件原文；删除、重命名、生成物及配置同样纳入。
- 完整需求矩阵、各切片完成条件、实际命令和日志位置、包 hash、外部 PASS/FAIL/BLOCKED；标明候选变化使哪些结果失效。

以上 diff 需要合并去重并核对当前文件，不能只看 HEAD 差异或已暂存文件。用户已有改动列为非本任务并保护；若与本任务相交，阅读上下文判断相互影响，不覆盖或顺带提交。审查者实际打开日志，不把实施者总结当作运行证据。

规范轴：逐项核对 AGENTS、对应 agent-docs、ADR、命名/目录/抽象/生成器、公开兼容和适用门禁；质量要求由 TESTING 决定，不降级处理既有失败。

需求轴：从原始来源核对每条 AC 的操作、预期、实现入口与决定性证据。检查请求内容、返回与副作用，身份、并发、期限、取消、失败停止和清理。区分 fake、replay、真实 socket、候选包、真实上游；计数、历史绿灯、skip 与仅看源码无法替代行为证据。

代码改动安排独立 reviewer，给出原始来源、当前文件、日志与授权范围，不预告期望结论。审查期间只读；实施者处理有证据的发现。问题注明位置、触发条件、后果、建议和严重性。无发现明确写无发现；不因缺凭据推测通过。

先列 actionable findings，再给两轴结论和每项门禁状态。FAIL 表示已知失败或要求未实现；没有已知失败但必要外部条件缺失为 BLOCKED；全部要求、门禁与证据满足才 PASS。修复后重新读取变化并重跑相关证据，最终结论绑定同一候选。审查包保存在当次 runs 记录，审查不自动提交。
