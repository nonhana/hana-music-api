# 请求动作与客户端身份分别声明

模块原来可以分别覆盖协议、UA 和 Cookie，歌单收藏甚至需要修改 Call 才能形成网页请求，因此选定单一请求链中的 profile 作为身份和协议的唯一来源，模块只声明实际动作及其 token、语义、缓存和重试资格。生成器与动态 loader 读取模块本地同一份声明，声明随 Call 冻结，用户会话继续来自每次调用；请求内核在发送前核对动作与目标并取当次 token，模块不再改 Call 或放置 token。

P1 只迁移歌单收藏，普通配置对其受控字段的覆盖已失效，Promise、业务输入、响应外壳和会话 Cookie 保持。其余模块的旧判定暂时保留在原执行链，生成的 `generatedPendingActionModuleIdentifiers` 明确列出未迁移范围；P12 在各批次完成后删去可选声明、旧默认协议和重复策略，普通模块配置的公开删除按 major 交付，显式底层 createRequest 仍保留目标与凭据安全校验。纯本地模块最终声明空动作集，多请求模块逐动作声明，不能用占位 profile 代表全部分支。
