# hana-music-api v7.0.0 打包构建与子路径架构重构

来源：交接文档 `hana-music-api-v7-packaging-handoff.md`、实施计划 `_notes/packaging-overhaul/implementation-plan.md` 与本次用户显式 `/hana-implement` 指令。

基线：分支 `feat/issue-140-playlist-steps`，起始 HEAD `59ee947b08f1806c5a6ada0a010473af8e7dbfe4`，受控工作区干净（仅 `.gitignore` 忽略目录 `_notes/` 中存在计划文档，无已有未提交用户改动）。

目标：以 v7.0.0 major 为边界，通过 `tsdown` `unbundle: true`、7 组公开子路径（`.`、`./api/*`、`./schemas`、`./schemas/*`、`./core`、`./utils`、`./watchman`）、组合式按需客户端 `createClient`、全仓精确 `effect/*` 子路径、极简依赖树（仅 `effect` 为必填依赖，`hono` 移入 `devDependencies`，`undici`/`music-metadata`/`qrcode` 转为可选 `peerDependencies`）与纯 Standard Schema v1 `.d.ts` 收口，彻底解决包体膨胀、Tree-shaking 失效、NFT 过度追踪、冷启动缓慢与 8.2 MB `.d.ts` 膨胀。

范围：实施计划 Slice 1 至 Slice 7 全部代码、代码生成器、生成物、测试、打包配置、ADR、工程与用户向文档、`.changeset/v7-packaging-overhaul.md` 及本地离线交付门禁与前后量化对比。

非目标：不修改网易云上游协议/加密/389 动作策略/业务字段松紧；不替换 `effect` 运行时；不修改下游仓库 `campanula-music`；不执行 `git commit`、`git push`、`npm publish` 或真实账号 live 写入。

测试 seam：单元规则（`tests/unit/`）、SDK/模块/架构边界行为测试（`tests/behavior/`）、原文响应回放（`tests/replay/`）、代理与负载传输测试（`tests/transport/`、`scripts/load-test.mts`）、候选 tarball 消费者/摇树/严格类型验收（`tests/package/`）、定向变异测试（`tests/mutation/`）。

适用门禁（按 `agent-docs/TESTING.md`）：

- 离线全仓验证：`bun run verify`（含 `types:modules:check`、`inputs:check`、`failures:check`、`schema:audit check`、`build`、`test`、`typecheck`、`lint`、`spell`、`fmt:check`、`docs:build`）
- SDK 包与契约验证：`bun run verify:sdk`、`bun run build:check`（`publint --strict` + `attw --pack . --profile esm-only`）
- 返回体结构与录制验证：`bun run verify:fixtures`
- 流量与 transport 改动验证：`bun run test:load:smoke`
- 定向变异验证：`failure-contract`、`module-config`、`browser-types`、`candidate-package`
- 真实上游 live（`LIVE_UPSTREAM=1 bun run test:live`）：不适用（本轮非目标明确不包含协议/上游变更，且用户未授予真实上游/凭据权限）

本次授权：允许实施 Slice 1–7 全部代码/测试/生成物/文档与本地离线验证；未经用户再次明确授权前禁止 `git commit`、`git push`、`npm publish` 与真实上游写入。
