### 已核对的基线与 profile

固定基线：`feature/refactor` / `c2c8fa1352578f146d3630b760b5de546f2ee3c7`，启动工作区干净。以下是源码调查和待验收合同，不是已经通过的运行结果。来源为该 HEAD 的 `src/modules/<模块>.ts`、`src/core/options.ts`、`config.ts`、`request-intent.ts`、`request-plan.ts`、`endpoint-policy.ts` 和 `call.ts`。表内源码链接固定到该 HEAD。

### 全模块动作基线（AC-01 至 AC-05）

每行 SDK 入口为 client 的对应 camelCase 方法、根具名函数及 invokeModule(identifier)，HTTP 路由为模块名中的 `_` 换成 `/`（例如 song_download_url_v1 → /song/download/url/v1），最终以生成器、SDK registry 和真实 HTTP loader 发现结果逐项核对。HTTP 支持的业务值按原 decoder 保持，不额外开放 execution config。

表内 data 保留源码表达式；query 是业务输入，未定义字段经原 JSON 序列化省略；通用准备另加 e_r=false，weapi 加 csrf_token，eapi 加 header，显式 checkToken 仅由既有协议编码规则处理。动态变量和分支补充见表后，所有成功分支一次 POST。

### 实际分支与边界（均须有最终请求对照）

- `album`、`artist_album`、`artists`：id 生成路径，分别限定 `/api/v1/album/`、`/api/artist/albums/`、`/api/v1/artist/` 的规范化边界；测试合法 id 与路径逃逸在发送前失败。`album_songsaleboard` 的 type 默认 daily，daily/week/total/其他字符串走非年榜正文，year 额外携带 year；动态路径限定 `/api/feealbum/songsaleboard/`，保留业务输入，不把 URI 片段当新目标。
- `artist_list`：initial 的字母/数字/省略与非法复合值；`artist_new_mv`、`artist_new_song` 的 before 有值/当前时间；`like` 的 String(like ?? '')==='false' 才取消，其余有效 primitive 为红心，保留输入不变。红心/取消均是 write，未传 token 不在本地拒绝。
- `playlist_import_name_task_create`：truthy local 优先，解析数组后只映射 name/artist/album 为 songName/artistName/albumName 并序列化 multiSongs；否则 playlistName 原值或带当地时间的默认名称，text 生成 encodeURI 的 rpc 导入 URL，link 随后覆盖 text，空输入 songs=''；错误 JSON/非数组保留原空数组结果。四个请求动作 local/text/link/empty 都为 write，不新增上游请求。
- `song_url` 与 `check_music`：br 的原 ?? 默认及 parseInt 行为；song_download_url 保留 || 默认，三者不强行统一。song_url 保留逗号 ID 字符串数组和顺序恢复；check_music 保留首项 code 判定和固定公开正文，不依据 URL 是否为空另写语义。
