收藏歌单改用官网的网页请求写法，并补充上游限制说明。

- `playlist_subscribe` 固定使用官网的 weapi 网页身份：`https://music.163.com/weapi/playlist/{subscribe,unsubscribe}`、Cookie `os=web`、浏览器 User-Agent，请求体只带歌单 `id`。调用方传入的 `crypto`、`os`、`ua` 对这个接口不起作用；入参 `id`、`t` 和错误合同不变，写操作仍不自动重试。
- 对照证据：同一会话、相近时间里，自称 `os=pc` 或 `os=iphone` 客户端但缺少客户端特征的请求会被单独以 405 拒绝；在已成功的官网请求里只加 `os=iphone` 就变成 405，去掉即恢复。2026-10-17 抓取官方 Mac 客户端确认，客户端每次收藏前约 0.1 秒向网易易盾申请一次性反作弊令牌，随后放在请求体、加密头和 HTTP 头中；SDK 没有正当途径生成同样的令牌。
- 已知局限：没有该令牌的请求在连续操作后会进入数小时的拒绝窗口。此时网页和 API 路径都会被拒，同一账号的手机 App 不受影响。SDK 原样保留上游状态码和说明，`retryAfter` 只是退避建议。2026-10-17 23:08 在全新会话、从未操作过的目标上仍返回 405，重复性验证尚未完成（#77）。
